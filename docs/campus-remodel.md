# 全校園重新建模（街景比對）進度

使用者要求（2026-11-18）：重新建模整個校園，包含建築物與內部細節（有資料的才做）；過程不用詢問；額度用完時，等額度恢復後自動接續。
本檔是唯一的進度來源：每次接續都從下列各清單中「狀態＝待辦」的第一項開始（先外觀清單，再室內檢查清單，最後校園共通項目），做完立刻更新本表並 commit + push。

## 規則（不可違反）
- Google 街景只能「用眼睛看」當參考（Google Maps Platform 條款）：不可下載、擷取像素、取樣顏色或存檔街景圖片；顏色用目測估計後手寫 hex。
- 不可 commit：`assets-src/photos/`、`assets-src/reference/`、平面圖 JPG、`.env.local`、任何 API 金鑰。
- 推送到 origin main 可以；不可 force push。commit 結尾加 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`。
- 回覆使用者用繁體中文。
- 龍潭路（兩段）已完成，不要再改；龍潭路兩側行道樹與台階依使用者指定保留。
- 已有手工建模的建築（管理二館 mb、管理一館 ma、圖書館 library、警衛室 mainGate）只檢查外觀色彩，不重做結構。管理三館沒有手工模型（ma 只取代管理一館），用一般 OSM 擠出＋自動室內。

## 每棟的流程
1. `preview_start {name:"dev"}`，視窗設 1280×760，按「繼續遊戲」，在 console：`(await import('/src/ui/chat.tsx')).runCommand('/streetview on')`。
   勘查輔助（src/tools/svSurvey.ts，只在開發模式）：
   - `await __sv.hits(<OSM id>)`：每面牆附近的全景（google＝街車、outdoor＝使用者上傳 360°，校園內大多是後者），依距離排序。
   - `await __sv.view(<OSM id>, k)`：角色站到第 k 個全景點、面向那面牆，面板跟著同步。
   - `__sv.big(true)` 放大面板看全景；`__sv.big(false); __sv.hide(true)` 看遊戲畫面。
2. 比對並記錄：樓層數 / 高度、牆面與飾帶顏色、玻璃顏色、開窗型式（punched / ribbon / curtain / blank）、開間寬、窗比例、一樓是否玻璃、陽台、遮陽板（水平 / 垂直）、柱列、雨遮、女兒牆、屋頂設備。
3. 寫入：
   - 外觀：`assets-src/campus/facades.json` 的 `buildings["<名稱>"] = { preset, style: {...} }`，然後 `npm run -s facades:build`。
   - 樓層 / 高度錯誤：`src/campus/campusFixes.ts` 的 `BUILDING_FIXES[<OSM id>]`。
   - 室內：只有本表「室內＝有」的建築才有平面圖資料（`public/data/buildings/plan-<id>.json`；注意 `src/config.ts` 的 `FLOORPLAN_INTERIORS = false`，遊戲目前用的是 `src/interiors/generateInterior.ts` 自動產生的室內，描圖資料只留在 repo）；在遊戲內走進去檢查房間、門、樓梯是否正常，有明顯錯誤才修。沒有平面圖的不憑空捏造室內。
4. 在遊戲裡同位置同方向截圖，確認與街景一致；`npx tsc --noEmit -p .` 通過。
5. 本表該列狀態改為「完成」並寫備註（改了什麼），每 3–5 棟 commit + push 一次。
6. 街景看不到的建築（校園深處、無街景）：狀態寫「無街景」，只做合理性檢查。

## 觀察備註
- 校園西側與龍潭路西段北側外圍是約 2 m 高的灰色水泥空心磚（鏤空花磚）圍牆；學人宿舍東側是黑色鐵欄杆＋矮牆。遊戲目前是黑色欄杆。
- 校內全景大多是使用者上傳的 360° 照片，載入要 15–25 秒；黑畫面通常是還沒載完，等久一點再截圖。
